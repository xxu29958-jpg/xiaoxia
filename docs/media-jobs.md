# 媒体任务协议（cover-v1）

网关是任务权威。新接口位于现有本地语音网关，使用原服务 Bearer 密钥。
调用方提供稳定 `X-Owner-Id`；渠道适配器必须从已验证身份得到它，不得让模型选择。
该服务密钥代表受信任的本地适配器，不是可以公开分发的用户凭据。

| 请求 | 行为 |
|---|---|
| `POST /jobs/covers` | 带 `Idempotency-Key` 提交，返回 202 和任务 ID。相同身份／键／参数读回同一任务；改参数返回 409。 |
| `GET /jobs/{id}` | 返回排队／运行／取消／失败／生成完成状态及分段进度，不含路径、源 URL 或租约。 |
| `POST /jobs/{id}/cancel` | 立即记录取消。运行中的处理到下一个检查点退出；完成后的作品事实保留，但禁止读取交付。 |
| `GET /jobs/{id}/events` | 当前身份的最近 128 项任务事件，按时间序列返回。 |
| `GET /jobs/{id}/result` | 仅已完成且未取消任务可读；先检查实际文件长度和 SHA-256，响应带 `X-Artifact-SHA256`。 |

正文参数：`source_path` 和 `source_url` 二选一；`acapella`、`pitch`（−12…12）、
`start_seconds` 和可空 `duration_seconds` 与原转换含义相同。拒绝额外字段、空源和非有限数字。
本地源复制后按内容哈希保存，后续改原文件不改变已接收任务。URL 只接受 HTTP／HTTPS；
下载完成后在当前租约下绑定录音路径／哈希，后续尝试使用实际绑定文件。

状态库位于 `voice_state/jobs/state.sqlite3`；输入、各次尝试及后端处理文件也在该目录内。
最多 32 个活动任务，一个网关工作线程；租约 30 秒，每 10 秒续租；最多 3 次中断恢复尝试。
输入和返回 WAV 各限制 2 GiB。容量满返回 429，已有请求的幂等读回仍可用。
这些上限不等于已完成全部归档／磁盘配额治理。

网关持有随机租约令牌，演唱服务直接检查同一状态库；每次请求的参数、声音参考和实现签名必须匹配。
两进程因此必须使用同一 `voice_state`。不支持悄悄退回无任务协议的旧后端。
新工作线程接管过期任务后，旧线程即使返回完整 WAV，也不能提交结果。
关闭服务停止续租，保留尚未完成的尝试；重启等待租约过期再恢复。未知数据库版本拒绝打开。

`completed` 只表示已确认生成结果，响应的 `delivery` 仍为 `not_recorded`。
没有发送回执就不能记为已发送、已播放或自动补发。取消之后已经开始传出的响应无法撤回，
因此渠道交付使用下面的独立持久事实，不修改网关的生成事实。

## 聊天消费与交付

插件 `ada_cover` 先持久接收请求，再立即返回请求 ID；`ada_performance` 按已验证身份查询或取消。
QQ／微信的同一主人可跨入口查询，作品始终回到原始会话。模型不能提供身份或投递目标。
附件复制为不可变输入；同一渠道原生消息、同一内容和处理参数只产生一个请求，附件临时路径、
显示标题及等效数字写法的变化不会另建任务。网关受理后响应丢失时，用同一请求 ID 重放，保留同一生成任务。

插件数据目录下 `performances/requests.sqlite3` 是聊天受理、取消意图和交付回执的权威；
其中的生成进度仅是网关观察值。输入在 `performances/inputs`，下载和完整 MP3 在
`performances/deliveries/<request>/<attempt>`。它们不参与聊天临时音频的七日清理。
最多 32 个活动请求，工作租约 60 秒，每 20 秒续租；编码和渠道发送分别最多等待 120 秒。
生成等待期间释放工作租约并轮询，不占用聊天工具调用。

| 交付状态 | 含义与恢复 |
|---|---|
| `pending` / `waiting` / `preparing` | 本地受理、等待生成或准备文件；过期租约可接管，旧工作者不能提交发送。 |
| `sending` | 已持久记下发送尝试；此后强杀或响应丢失只能进入 `unknown`，不能自动重发。 |
| `accepted` | 留有渠道服务端返回的原生消息 ID；不表示手机已经收到、打开或播放。 |
| `unknown` | 发出后的结果不确定，或适配器没有暴露原生回执；保留文件和尝试供后续对账。 |
| `cancelled` / `failed` | 发送前取消／失败；保留生成观察、错误和原有事实。 |

发送前重新校验主人绑定、原渠道、文件大小／SHA-256 和网关取消状态，再以事务记录发送开始。
本地取消在该事务前生效时禁止发送；已经开始的渠道请求无法撤回。取消之后迟到的真实回执仍可保存，
不能把已经发生的发送改写为“未发送”。生成失败仅发送一次明确的失败通知，记录 `failure_notice`，
不冒充已经完成作品。取消请求不另发外部通知。

QQ 使用 [OneBot v11 `send_private_msg`](https://github.com/botuniverse/onebot-11/blob/master/api/public.md)
返回的 `message_id` 保存服务端接收事实。微信目前沿用现有适配器发送附件；
`Context.send_message` 的布尔值只说明找到适配器，因此记录 `adapter_returned` / `unknown`。
不会把本地随机 UUID、函数返回或生成完成当作原生收发回执。微信原生回执暴露、未知结果对账、
真实手机读回和人工听审仍待完成，快速测试只使用隔离回环服务和测试渠道接收器。

## 兼容与剩余边界

旧 `/cover` 和 `LocalVoice.cover` 保留兼容；插件默认演唱已改为持久任务消费。当前 Fish 的 GPU 请求锁仍覆盖整首转换，
新的任务状态／取消接口不占用该锁，但实时说话与演唱争用还需后续资源调度验证。
两个持久库、作品、源录音应作为同一恢复集合；存储回收和完整备份／迁移入口尚待 M7 实现，
不建议手工移动部分目录。
