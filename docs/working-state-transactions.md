# 未完事项与目标的连续状态

适用：M1 的未完话题、共同玩笑与明确目标。`DialogueState` 的原 JSON 写入器和内存当前值已退役；
聊天工具、最终回复候选、语义收尾、提示、主动候选和管理端统一访问原生 MemoryStore。
原有 `cross_window_threads` 仍是跨窗口传话队列，不承担这些工作对象的权威。

## 对象与来源

- `working_objects` 保存每位已验证主人的当前对象；`working_revisions` 保存同库修订。
  QQ／微信共享主人作用域；Web 管理员试聊有独立作用域。模型不能选择主人、消息 ID 或渠道身份。
- `topic`、`shared_joke` 沿用 7／30 天的可及期；读取不会延长期限。`goal` 不因沉默或隔天到期。
  修改已有目标时，省略 kind 会保留其类型。过期对象仍可显式查询，不伪装成已完成。
- 原生用户表达、转写、模型形成的内容、管理操作和 legacy 来源分开标注。保留原生 ID、渠道、
  原始发生时间（平台提供时）、本机接收顺序、记录时间与支持原文。确切引文校验不等于语义判断正确。
- `resolve`／`cancel` 表示来源支持的结束／取消；`resolution_basis` 明确不是外部执行回执。
  演唱、桌面、消息投递仍须各自的实际结果，不能把工作目标的关闭当作已经办完。

采用 [CoALA v3 §4.1、§4.6](https://arxiv.org/html/2309.02427v3) 中跨模型调用保持当前目标、
内部推理／记忆与外部行动分开的组织方向。数据库模式和版本归并是项目工程选择；不声称复现论文效果。
联想、评价、效用学习与巩固仍保留在完整合同范围内。

## 归并、查询与消费者

写入复用 MemoryStore 的连接、锁、`BEGIN IMMEDIATE`、恢复及关闭屏障。
当前值、历史、名字绑定和幂等回执同事务提交；失败或提交前授权撤销整体回滚。
版本取自模型实际收到的提示／list 快照，语义收尾使用生成开始前的版本；不会临提交重新读版本冒充旧决定。
接收较早的消息不能覆盖较新消息形成的内容。此顺序是本机观察，不是所有平台的全局真实时间排序。

同一原生消息及对象的相同意图重放返回原回执，`replayed` 与 `current` 分别表示历史重放和当前有效性。
同键异意图拒绝；旧消息不会复活已关闭／遗忘的对象。每次修改有独立 version；删除后同名重建不会
使旧回执重新有效。名字哈希绑定保留重命名前的身份，避免旧消息因名称改变绕过去重。

`ada_threads` 提供 list、history、save、resolve、cancel、forget。list 默认 12 条，支持字面关键词、
过期／关闭对象和翻页；分页中的对象集合、排序或条件改变时要求重新查询。history 每页 20 个修订，
来源正文最多返回 2000 字并标明截断。提示只是工作集，模型可继续检索，不等于已经读过所有经历。

主动候选携带实际选中的对象版本，发送前同一 id 的内容变化也会使候选取消。
最终回复中的可选状态写入保留结果；失败明确进入实际回复与后续历史。
管理端关闭按客户端读到的 version 在事务内检查；页面区分目标、无事项、读取失败和有界列表。

取消异步调用的等待，不意味着正在执行的 SQLite 事务自动撤销。已进入事务的操作由原生关闭屏障
收束；重启后查询实际状态／回执。事件在提交前明确停止则拒绝提交；已经提交的旧操作可重放查询，
不会再次执行。不能仅凭调用被取消宣称数据未写入。

## 迁移、撤销与恢复

Schema 增至 `memory-atom-v2-working-state-v1`；原生一致性备份先于升级。
首次访问先验证整个 `dialogue.json`，仅导入已验证作用域，并把对象及导入标记原子提交。
保留旧 ID、时间和文件原始字节，来源标为 legacy，不补造原消息或已丢失的历史。
同名旧项保留各自 ID，修改时必须明确选择；冲突／损坏保留原件并显式报不可用。

`working_imports` 按主人及原渠道保存原始字节哈希。重启不重新覆盖已有修改或恢复已遗忘内容；
之后明确加入并验证的另一渠道可导入其尚未采用的旧项。标记不依赖安装目录，数据库备份与原文件
一起移动／恢复后仍能读取。采用后旧文件发生变化会明确报错，需要核对来源，不回退到旧 JSON 写入。

若事件已有 SourceCapture 回执，沿用并在事务内验证；撤销当前来源删除对应工作对象，撤销旧来源
移除对应旧修订。forget 删除当前值及全部修订。原生私人记忆清除会删除该来源参与的整个工作对象，
全量清除会删除全部当前对象及级联历史。`working_operations`、`working_names` 和导入标记保留最小
摘要／回执，不含消息正文，以防原消息或保留的 JSON 自动复活被清除内容。
原文件与一致性备份的保留／销毁属于独立恢复与遗忘管理；本切片不会擅自删除它们。

## 验证边界

自动入口使用临时 ASTRBOT_ROOT、真实 AstrMessageEvent／MemoryStore、两个 SQLite 连接和实际消费者。
覆盖并发插入／CAS、十次重放、改名／关闭／遗忘／重建、迟到来源、授权撤销、事务故障、
提交前后进程强杀、取消等待及关闭屏障、原子 JSON 迁移、后来加入的渠道、schema 备份和恢复搬迁。
Chrome 无头浏览器执行真实管理页脚本，点击后将原版本传给原生管理端，再读取实际存储更新页面。
这只验证管理组件的状态与操作，不等于完整页面视觉验收。

此处不验证真实模型的理解／抽取正确性、真实 QQ／微信连续聊天、完整认知备份恢复或人的使用体验。
生产数据尚未迁移，运行服务及 QQ 四秒声音身份保留；完整 M1、G1／G2／G3 未据此宣称完成。
