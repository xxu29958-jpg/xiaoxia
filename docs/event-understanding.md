# 事件理解的修订与消费者

该域保存小夏对一个已收到事件的解释，以及这一解释对相关接话的含义。
它是带来源的模型推测，不是新的用户事实、长期偏好、任务完成回执或情绪刺激次数。
工程进度与验收状态只维护在 [v1.3 台账](delivery-v1.3.md)。

## 权威与当前路径

- 当前值、修订历史和操作回执都属于原生 `MemoryStore` 同一个 SQLite 数据库，
  使用其锁、事务、异步操作恢复屏障和备份。Ada 的 `EventUnderstanding` 不维护第二个当前值缓存。
- 身份授权复用 `DialogueState` 对当前 owner、已验证渠道、实时插件实例、停止事件与网页读取隔离的检查；
  每次读写重新取当前 store。原有 dialogue.json 仅按既有协议迁移工作事项，不保存解释。
- `ContextBuilder` 把当前解释及原始原话、最新支持来源交给模型。
  `ChatReplyer` 在同一次原生生成的最终 JSON 中消费可选 `appraisal_updates`，不另调一次模型。
  只向聊天历史保留实际说的话。保存失败会在回复中说明，没有把模型生成的保存意图当成已保存。
- 主动候选读取同一份解释快照，交给当前生成。真正投递前重新检查快照版本；
  生成期间新增、修改或撤回解释会使旧候选失效，候选本身不是已发送事实。

## 数据与约束

一个新解释的 id 由 owner 和真实原始消息身份确定。一条来信最多新建一个事件解释；
同条消息再次生成不同内容不会另建事件，而是返回操作冲突。对既有事件的新解释沿用已读 id。
本轮最多接受两个独立候选；每项单独事务，不能把两项的部分成功说成批次原子成功。

每个版本包括原始来源／原话、最新来源／原话、事件短名、当前理解、对相关接话的含义、
剩余不确定性、active/resolved 状态、修订号和不透明版本。resolved 不证明外部事情完成。
字段有长度上限，证据必须是当前私人用户消息的连续引用，存储前沿用原生凭据脱敏。
没有用户反馈不能据沉默制造更新；读取、回忆或展示解释不会增加修订号、证据或旧情绪事件数量。

写入按原生消息身份幂等，校验本轮快照的预期版本和来源接收顺序。
不允许没读到对象就覆盖它，也不允许迟到回复替换更新的解释。事务末尾再次核对身份与停止状态。
如果来源经过原生 capture，读取和修改还核对全部支持修订的当前 capture 版本。
源更正导致不再有效的解释不会进入提示；撤销任一支持来源时，整条派生解释和修订都会撤回。

当前提示最多提供最近 8 项，底层最多 20 项；历史分批读取 20 个版本。
快照给出总数、截断与来源失效数量，失败不是“没有记录”。当前选择只按更新时间有界展示，
没有把它命名为语义联想、时间激活、效用学习或自然遗忘；这些仍需独立机制和效果证据。
`emotion_events` 的类型化交付、工作对象和核心事实各保留原权威，没有把该解释写成另一份情绪事件。

## 取消、清除、迁移与恢复

新增表为 `appraisal_objects`、`appraisal_revisions` 和 `appraisal_operations`，
schema 版本为 `memory-atom-v2-working-state-v1-appraisal-v1`。升级前按原生流程备份旧库。
写入途中异常／停止会整体回滚；真实进程在提交前或提交后退出，重开后分别重做或返回原回执。
取消协程不绕过原生正在执行的数据库操作关闭屏障。

原生私人清除会检查所有修订的支持者，并清除派生对象；全量清除也覆盖该域。
仅保留不含原话的哈希操作回执，阻止旧事件重放复活已清除内容。原生备份保留及恢复规则沿用，
备份是另一份保留数据，不把清除在线库说成删除所有历史备份。

## 理论关联与验证边界

[EMA 原论文](https://stacymarsella.org/publications/pdf/EMA_Dynamics.pdf) 把随感知和推理变化的事件解释，
与基于解释的评价及后续应对选择分开。本实现借鉴这种组织关系，保留可撤回的解释和来源，
不声称复现 EMA 的因果推理器、全部评价变量或情绪动力学，也没有采用其部分情境中的完全可观察假设。
模型提出的因果理解仍可能错，版本、原话和不确定性让后续更正可以沿同一事件进行。

自动检查覆盖真实原生存储、回复／提示／主动候选消费者、跨渠道身份、冲突和重放、来源更正／撤回、
私人和全量清除、旧 schema 备份、恢复搬迁以及真实进程强杀。
真实模型旅程另外固定输入、模板和生成配置，保存完整回复；受控旧／新／空状态对照只检验该状态的影响。
它故意隔离其他聊天记忆，不能替代全系统注意、长期学习、真实手机往返或自然听感验收。
