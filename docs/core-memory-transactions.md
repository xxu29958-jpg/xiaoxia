# 共享核心记忆的事务与来源

适用：M1 第一条路径——`ada_core_memory` 和已认证管理端对 QQ／微信同一主人核心约定的修改。
原生 `MemoryStore.memories` 继续保存当前有效值；没有新增并行事实库。

## 写入路径

`OwnerMemory.observe` 在收到私聊时记下本实例严格递增的接收顺序。
聊天工具从实际事件取得原生消息 ID、渠道、用户、机器人及可见正文；模型不能传入这些身份。
语音预处理产生的 Plain 文本标为 `speech_transcript`，不把转写当作原始录音的逐字证明。
正文与工具生成的记忆内容分开保存，后者标明 `model_tool_interpretation`。
模型对“这是否应长期记住”的理解仍需实际聊天验收；来源绑定不等于语义判断必然正确。

适配器按已验证原生作用域读取同名块，创建一次意图。事务使用已有连接、关闭屏障及
`BEGIN IMMEDIATE`，在提交前检查身份绑定、同名成员集合和每份记录的版本。
任何一个写入失败都会回滚全部当前值、修订历史和操作回执。既有管理端的 expected 内容检查
与原生版本 CAS 同时保留；不允许读完以后新出现的另一渠道副本被静默遗漏。

相同原生消息、同一标签使用同一操作键。相同意图重放返回原回执；同键不同内容返回冲突。
相同文字来自另一条原生消息仍是新经历。曾经成功的旧写入再次到达时不会重新生效。
回执的 `replayed` 表示重放，`current` 表示该版本现在是否仍有效；调用方不能把历史成功
宣称为当前刚完成。每次写入还有独立版本标识，删除后以同一标签重建也不会误认成旧版本。

收到较早但模型处理较晚的聊天请求不能覆盖较新接收的约定。这是本机实际接收顺序，
不是声称能够恢复平台端所有消息的真实发生顺序；跨系统时钟或漏掉的旧平台消息不由本切片解决。

## 当前、历史与遗忘

- `memories`：原有读取／提示入口使用当前记录，继续遵守主人、会话、机器人和原有人格范围。
  新共享块保留旧实现的私有共享人格语义，不能因改造而让不带 persona 的跨渠道提示读不到它。
- `core_memory_revisions`：同库保存修订内容、原消息来源、原生发生时间（若平台提供）、记录时间。
  既有数据首次修改时保留旧快照，来源标为 legacy；不补造已经被旧代码覆盖的历史。
- `core_memory_mutations`：同库保存操作摘要和回执，不保存原消息正文。重启或确认响应丢失后可以
  查回提交事实；最小去重墓碑保留，避免旧事件复活已遗忘内容。
- `ada_core_memory(action="history", label=...)`：按原生可见性读取每个当前块最近 20 个修订；
  每条来源正文最多返回 2000 字，返回覆盖说明及正文截断标记。它不是完整聊天历史接口。
- 凭据使用原生敏感数据规则脱敏，来源标记是否发生脱敏。缺原生消息 ID、可见正文、接收观察
  或有效主人身份时不会提交聊天修改，也不会回退为管理端确认。
- 若当前事件已有原生 SourceCapture 回执，复用并在事务内检查其当前版本；不启用第二个采集实例。
  删除核心记忆会级联删除其修订。撤销采集来源会沿原生引用删除仍依赖它的当前记忆，并移除
  相应历史来源；已有独立新来源的当前约定保留。完整备份的保留／销毁另属恢复与遗忘验收范围。

## 迁移、失败与证据

原生 schema 版本增为 `memory-atom-v2-core-state-v1`，新表及触发器都是增量加入。
原有 SQLite 一致性备份在 schema 变更之前执行；生产聊天库尚未迁移。
现有单块 `save_core_memory` 接口保留返回形状和版本冲突码，仍供管理端／旧消费者使用。
该兼容接口的旧原生聊天工具还未全面迁入带事件意图的共享写入，不能宣称所有记忆入口已统一。

`tools.quality.gate --base <本次基线> --bot-python <Python 3.12>` 自动选择认知契约。
测试使用临时 ASTRBOT_ROOT、真实 AstrMessageEvent、原生 SQLite、实际 MemoryTools 和提示读取器；
不打开生产聊天库，不向 QQ／微信外部账号发送消息，不使用真实 LLM 或验证语音识别准确度。
包括两份写入间故障／进程强杀、提交后强杀、双连接 CAS、十次重放与重开、成员变更、撤销绑定、
来源撤销、删除重建、旧 schema 备份与迁移，以及旧记忆／来源采集和聊天演出消费者回归。

本切片未实现图联想、ACT-R 激活、事件评价、效用学习或睡眠巩固；不据此宣布 M1 或 G2/G3 完成。
